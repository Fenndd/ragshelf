## Findings

### T004-REV-01 — major — Restore environment initialization before model-library imports

**Location:** `src/ragshelf/generation/rag_chain.py:1–2`; integration path in `src/ragshelf/app/streamlit_app.py:2–4`.

**Evidence:** T004 removes the module-level `load_dotenv()` from `rag_chain`. The existing Streamlit app imports that module before `DynamicVectorStore` and the embedding libraries. Previously, a `.env` copied from the supplied template set `HF_HOME` and the telemetry opt-out before Transformers imported Hugging Face. The replacement imports configuration but does not call `apply_environment()`. A search of `src/` and `tests/` found only the helper definition and its test, no production call.

In a fresh process, the reviewer cleared the HF/MinerU cache and telemetry variables, enabled `HF_HUB_OFFLINE=1`, imported `rag_chain`, and inspected Hugging Face constants without loading a model:

```text
HF cache inside repository: False
HF cache is default user-profile cache: True
HF_HOME initialized: False
HF telemetry disabled: False
```

A separate fresh-process control simulated the previous setup using `load_dotenv(stream=StringIO(Path('.env.example').read_text()))` before importing Hugging Face. It used only the public template, not real credentials:

```text
HF cache inside repository: True
HF telemetry disabled: True
```

The independent worker also reproduced the current behavior by importing `rag_chain` followed by `dynamic_vector_store`, with an audit hook rejecting network connections and DNS resolution. No model constructor was invoked.

**Consequence:** for a normal Streamlit launch without inherited cache overrides, PDF processing instantiates `CombinedEmbedder` (`streamlit_app.py:32`). Its SciBERT client uses a remote model ID and `from_pretrained()` without `cache_dir` (`embeddings/scibert_embedder.py:5–9`), so model downloads/cache can go to the user profile instead of the project. This conflicts with R8 (`docs/requirements.md:16`) and ADR 0001 (`docs/decisions/0001-model-stack.md:47`). The previous Hugging Face telemetry opt-out is also lost. The review established cache selection and opt-out state, not an actual download or telemetry transmission. The current app does not use MinerU, so no newly exercised MinerU telemetry regression is claimed.

**Proposed fix:** initialize `apply_environment(load_settings())` at the existing application boundary before importing Transformers, sentence-transformers, or Hugging Face. Inspect other affected entry paths for the same ordering requirement. Calling the helper only inside `generate_paragraph()` would be too late. Keep credential loading in `load_secrets()`; do not restore ad-hoc key reading with `load_dotenv()` in callers.

**Verification required:** add an offline fresh-process regression test for the actual application import path that checks the project-local HF cache and telemetry opt-out without downloading or loading a model. Confirm the failure before the fix and success afterward; rerun affected tests and the full fast suite. The existing `test_apply_environment_sets_project_local_folders` checks the helper itself and does not detect missing production initialization.
