## Confirmed findings

### T006-REV-01 — [P1] Bundle selection ignores the current HTML source context

**Location:** `src/ragshelf/documents/loader.py:67` (`locate_bundle`, candidate validation and final selection at line 77).

The function enumerates every bundle under a source's `content_hash`, validates each saved parser descriptor against that same saved descriptor, then selects the newest manifest by modification time. It does not verify that a candidate's `html_context` belongs to the current source or matches its current dependencies. T005 deliberately includes source URI and consumed local-resource hashes in HTML cache identity.

**Executed reproduction:** using the existing synthetic `HTML` fixture and `NativeHtmlBackend` in `tests/parse/test_html.py`, create byte-identical `a/document.html` and `b/document.html`. Give `a/style.css` `.hidden {display:none}` and `b/style.css` `.hidden {display:block}`. Run `parse_library`, make the `b` manifest newer, then call `load_library` with the same settings.

Observed results:

| Stage | `a/document.html` | `b/document.html` |
| --- | --- | --- |
| T005 native parse, 2 parsed / 0 failed | Hidden synthetic text absent | Hidden synthetic text present |
| T006 `load_library` | Hidden synthetic text present; uses `b` parser key | Hidden synthetic text present; uses the same parser key |

The manifest timestamps were set to 1000 (`a`) and 2000 (`b`) to make selection deterministic. Checks confirmed that both original bundles had the correct, distinct content before loading.

**Impact:** a document receives parsed text from another source context, even immediately after a successful parse-only ingestion. The document identity guarantee is broken and later indexing can ingest incorrect content under the first document's ID.

**Smallest viable fix:** filter candidates for applicability to the current source, including its HTML source URI and current consumed local dependencies, before selecting a valid bundle. Reuse `ragshelf.parse.html.html_dependencies` and the owning parse identity contract; validating output checksums alone cannot establish source applicability. Keep the path free of model-runtime imports.

**Fix verification:** add a regression for the two-source case above and for changed local dependencies with unchanged HTML bytes. Verify correct per-source content/key, explicit failure when no applicable cache exists, and unchanged lightweight `inspect` behavior.

### T006-REV-02 — [P2] Markdown list normalization discards evidence needed to separate references

**Location:** `src/ragshelf/documents/markdown.py:117` and `:124` (`markdown_items`, retaining only `entry[3]` / `match[3]`).

The adapter removes ordered-list markers before reference classification. For an ambiguous reference heading such as `Literature`, `references.py` requires bibliographic evidence; a numbered lead-in is one of the accepted markers, but Markdown normalization has already discarded it.

**Executed reproduction:** build a document from this synthetic Markdown:

```markdown
# Note

Body.

## Literature

1. Smith (2020). First work.
2. Jones (2021). Second work.
3. Brown (2022). Third work.
```

Observed: `document.references == ()`; the heading and list remain in the body. As a discriminating control, restore only `1.`, `2.`, `3.` to the generated `list_items` and rebuild: two reference blocks are separated (the heading and list), leaving only `Note` and `Body.` in the body. This confirms the loss of numbering as the cause, rather than a general unsupported-heading limitation.

**Impact:** bibliography entries remain available to future chunking/indexing, contrary to ADR 0002's requirement to keep the reference list outside the index.

**Smallest viable fix:** preserve ordered markers in list entries, or carry numbering structurally into reference detection. Preserve the distinction between a bibliography and ordinary numbered steps; do not classify all ordered lists as references.

**Fix verification:** add this golden case plus a negative ordinary numbered-list case. Verify that reference detection and the body-leakage counter agree on retained numbering.

### T006-REV-03 — [P2] Markdown tables without outer pipes become ordinary paragraphs

**Location:** `src/ragshelf/documents/markdown.py:18` (`_TABLE_LINE`, used by `markdown_items`).

The header matcher requires a leading `|`, although pipe-table syntax permits omitted outer pipes and the delimiter-row matcher already accepts that form.

**Executed reproduction:** build a document from `# Note`, a blank line, and:

```markdown
Name | Value
--- | ---
a | b
```

Observed: one paragraph, `Name | Value --- | --- a | b`, instead of a table block. The equivalent fixture with outer pipes produces a table.

**Impact:** row boundaries and the structural table type are lost, preventing the future chunker from preserving that table as a whole.

**Smallest viable fix:** accept a header without outer pipes when followed by a valid delimiter row; retain the original table rows. Do not treat every paragraph containing `|` as a table.

**Fix verification:** golden cases for both pipe styles and a negative prose-with-pipes case.

### T006-REV-04 — [P2] `inspect --all` emits unsanitized DOI terminal controls

**Location:** `src/ragshelf/documents/render.py:75` (`format_table`, DOI output).

Title and authors use `_one_line` / `_safe`; DOI is interpolated directly through `_value`. `normalize_doi` accepts some non-whitespace control characters from a sidecar. The single-document `format_inspect` path already sanitizes DOI.

**Executed reproduction:** write a synthetic sidecar as `json.dumps({'doi': '10.1234/a\x1bc'})`, read it through `read_sidecar`, build the document, and render it using `format_table([LoadResult(source, document)])`. The result retains the actual ESC character: `chr(27) in output` is `True`. Only `repr` was printed during inspection, so the escape was not executed by the terminal.

**Impact and broken guarantee:** untrusted metadata reaches the terminal without the promised control-character sanitization. `ESC c` is a terminal-reset sequence and can reset or distort the user's metadata listing. This finding does not claim shell-command execution.

**Smallest viable fix:** apply `_one_line` to DOI as to adjacent string fields. Optionally reject controls during DOI normalization as an additional defensive measure.

**Fix verification:** a sidecar-to-`inspect --all` regression must confirm no raw C0/C1 or bidi control reaches output. Keep the single-document output safe too.
