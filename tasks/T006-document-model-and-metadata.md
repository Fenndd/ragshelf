# T006 — Build the document model and metadata extraction

## Goal

Turn cached parser output into a normalized document with ordered, typed blocks, page numbers, a separated reference list, and metadata.

## Sources

- [Requirements R2, R3, R6](../docs/requirements.md)
- [Chunking and identity in ADR 0002](../docs/decisions/0002-pipeline-architecture.md)

## Scope

In scope: `Document` with metadata (title, authors, year, DOI, language) and blocks (heading level, type: paragraph/list/table/equation/code/caption, text, page). Normalization: Unicode NFC, hyphenation across line breaks, repeated running headers and footers. Reference list detected from headings in any language MinerU reports and kept apart from the body. Metadata from MinerU title and author blocks, PDF metadata, a DOI pattern, with sidecar values overriding. `ragshelf inspect <doc_id>` prints metadata and the heading outline.

Language clarification accepted by the user on 2026-11-19: document language comes only from the sidecar (`language` or `lang`); otherwise it is unknown (`None`). No automatic document-language labels are generated. See [ADR 0002](../docs/decisions/0002-pipeline-architecture.md#document-language-metadata--clarification-accepted-2026-11-19).

Out of scope: Chunking (T007). Parsing individual references into fields.

## Acceptance Criteria

1. Golden tests on synthetic Markdown/content-list fixtures check block types, pages, headings, normalization, and reference separation.
2. A sidecar value replaces the extracted value for that field only.
3. `ragshelf inspect` runs for every document in `data/library/`; a table of extracted title, authors, year, DOI for 10 documents is reviewed by the user.

## Checks

- `venv/Scripts/python.exe -m pytest tests/documents`
- `venv/Scripts/ragshelf.exe inspect <doc_id>` on each document.
- Manual: user spot-check of 10 documents, outcome recorded in Result.

**Design decisions.**

- *Identity and cache.* `doc_id` and the content hash come from `scan_library`. The bundle is found under `data/cache/parse/<hash>/*` and validated with the existing `cache_valid` using the manifest's own descriptor (no checksum logic here). With several valid parser entries the newest manifest wins. A missing or invalid entry raises `ParseCacheMissingError` ("run 'ragshelf ingest --parse-only' first"). Text passthrough bundles (`.md`/`.txt`) are rebuilt from `markdown.md` (one logical page 1); everything else uses `content_list.json`.
- *Block mapping.* `text` with `text_level >= 1` is a heading (level kept, 1 to 6); other `text` and `page_footnote` are paragraphs; `list` is a list; `table_body` is a table; `equation` text is an equation; `code_body` is code; image, chart, table, and code captions and footnotes become `caption` blocks (a caption precedes its table or code). Parser-labeled `header`/`footer`/`page_number`/`aside_text` and `index` (contents pages) are dropped and counted. Images contribute their captions only.
- *Characters.* Unicode NFC. Removed everywhere except code: BOM, zero-width space, word joiner, soft hyphens, and C0/C1 control characters except tab and line feed (so a terminal escape sequence in a title cannot reach the output). The zero-width non-joiner and joiner are spelling in Persian, Indic scripts, and emoji sequences, so they are removed only between two Latin or Cyrillic letters. A soft hyphen right before a line break joins the two halves of the word (such a join is not counted in `report.dehyphenated`). Code blocks get NFC, normalized line endings, and trimmed trailing spaces, nothing else.
- *Dehyphenation.* Only "left-" + line break + "right" with a lowercase continuation is joined. The hyphen is kept (and the line break removed) when the left token already contains a hyphen or ends in a digit, the continuation starts uppercase ("Smith-Jones", "COVID19-related"), the left part is one letter or all capitals or the continuation is one letter ("x-ray", "t-test", "e-mail", "DNA-binding"), or both halves are whole opposition words ("left-right", "input-output"). Never joined either: a fragment inside a URL, e-mail address, or DOI (the chunk before the break starts with "www.", "http", "10.NNNN" or contains "/" or "@", or the word after the break is followed by "@", "/", or a domain tail such as ".com"); a function word after the break ("short-" / "and long-term" becomes "short- and long-term", unless a hyphen follows that word, as in "end-" / "to-end", which stays one compound); a particle after the break ("built-in", "plug-in"). If the document itself spells the joined word unbroken elsewhere, join; if only the hyphenated form occurs elsewhere, keep the hyphen. Without such evidence a short list of compound prefixes (self, well, non, anti, ...) or suffixes (-based, -related, -free, -thirds, ..., Russian -то/-либо) keeps the hyphen; otherwise join (there is no dictionary, so "long-" / "term" becomes "longterm"). The look-back for the address check is bounded (256 characters), so a hard-wrapped paragraph of any length is processed in linear time. A line break without a hyphen becomes a space. Code, tables, and equations are never dehyphenated.
- *Running headers and footers.* Among the first or last two blocks of each page, paragraphs of at most 120 characters are keyed by casefolded text. Digits are masked only when the whole paragraph is page-number-like (a bare number, "page N", "N of M", "N / M", a page range "12-14"), and a Roman-numeral page number ("iv", "page xii") becomes one token. Every other text keeps its digits, so numbered labels ("Example 1."), short paragraphs that differ in a number, and captions ("Fig. 2") are never taken for repeats; the price is that a header which embeds its own page number inside longer text is not recognized and stays in the body. `page_footnote` blocks and a paragraph directly under a table (a table note or source line) are never candidates, and neither are headings, captions, or tables. A key is removed when it occurs on at least three distinct pages and a quarter of the pages, or on at least five pages filling 80% of its own page span (chapter headers in long books). Documents of fewer than 6 pages are left alone. A title repeated within one page counts as one page, so it stays.
- *Reference list.* A heading (or a paragraph of at most 60 characters) whose numbering- and accent-stripped, casefolded text exactly equals a known phrase starts the list (en, ru, uk, bg, sk, cs, de, fr, es, it, pl, pt, nl, hu, tr, ro, el, sv, da, no, zh, ja, ko). "7. REFERENCES", "VII. References", "Chapter 9: References", and decomposed accents match; "Literature Review" and "References to Violence in Media" do not. Bare words that are often a chapter title ("Literature", Литература, Literatúra, Literatur, "Sources", and so on) count only if at least two thirds of the entries that follow are citation-shaped in a strict sense (at most 450 characters, a year, and something prose lacks: a DOI/URL, "et al.", a [n] or "n." lead-in, a volume/page pattern ("pp. 3-9", "12(3)", "С. 12", "//"), or the author in entry position ("Smith, J.", "Smith J. 2019", "A. Smith,"); author initials and a year somewhere inside a sentence ("In 1850 N. Hawthorne published a novel") are prose) and there is at least one entry. The same strict test applies to a bare keyword paragraph. A section opened by a heading runs to the next heading at a higher level, or to an appendix/acknowledgements/funding/back-matter heading ("About the authors", biographies, index, glossary) at any level, and ends at the first table, figure caption, equation, or code block; deeper sub-headings inside belong to the list, and so does a sub-heading at the same level ("Journal articles", "Books", "Web sources" when the parser reports one heading level throughout) when at least two entries follow it, two thirds of them citation-shaped (parser-labeled entries count as such); a same-level heading followed by prose, or by a single entry, ends the list; several lists per document are all collected. A short paragraph that merely reads like such a heading (typically a line of a contents page the parser did not label) opens a list only when citation-shaped paragraphs follow, and holds only that run (one non-citation entry inside it is tolerated, two in a row end it); otherwise it stays in the body. Lists the parser labels `ref_text` are references even without a heading, and the entries around them go with them: from each labeled block, adjacent paragraphs and lists that are mostly citation-shaped or mostly numbered ("12. ...", "[12] ..."; up to 1,500 characters; a short numbered line counts only if it ends like a note, so "5. Conclusions" does not) join the references in both directions, and going forward a heading joins too when the entries after it are mostly citations, or are all entry-like and lead into a labeled block or into a heading that belongs to the list (a note section organised by chapter name). A heading followed by plain numbered paragraphs alone (numbered exercises under the next chapter) stays in the body, and so does a heading before a per-chapter labeled list; plain prose between entries ends the run. `BuildReport.reference_like_in_body` counts the numbered, citation-shaped entries that remain in the body and `inspect <doc_id>` prints it as "Check: N numbered, citation-shaped entries remain in the body" (a leakage measure; a few are normal). Language-independent fallback for a heading outside the keyword set: a run at the end of the document (after the last heading) of at least three paragraphs or list entries, four in five of them citation-shaped, is the reference list together with its heading; something must remain in the body. The scan is linear in the number of blocks.
- *Metadata.* Title is the first `text_level == 1` item on pages 1 to 2, cleaned like body text. If that whole heading is a section name ("Abstract", "1. Introduction", "Résumé", and the generic "Background", "Methods", "Results", "Summary", "Preface", "Einleitung", "Wstęp", ...) or has no letter, the title is unknown, not a later heading; a title that merely starts with such a word ("Introduction to Algorithms", "Abstract Algebra", "Methods: A Practical Guide") is a title and keeps its authors. Authors are the first name-like text line after it (affiliation, abstract, notice, and label lines such as "Chapter One", "Technical Report", "Lecture Notes" rejected; the affiliation test runs after e-mail addresses are removed (also in parentheses or angle brackets), so "Jane Smith (jane@x.org)" is a byline, and Czech/Slovak "ústav" is matched as a word, so Gustav, Gustavo, and Gustavsson are not rejected (the accent-free "Ustav" counts only before a lowercase word: "Ustav informatiky" is an institute, "Ustav Patel" a person); marks, emails, and numbers stripped; scripts without letter case such as Chinese, Japanese, Arabic count as name-like); ";", "and", "&" separate authors, and commas do except that "Last, F., Last, F.", "Last, First" pairs, and suffixes ("Jr.", "PhD") stay with one author, and initials keep their final period ("Smith J.A."). Year comes from copyright/published/received notices in parser-labeled furniture and early notice-like paragraphs. PDF metadata is read read-only with `pypdf` (`strict=False`; an encrypted file is tried with the empty password and gives nothing if that fails; pypdf's log and warning output is suppressed; a missing, damaged, or garbage file gives nothing). Placeholder titles and authors such as filenames, "Untitled", "PowerPoint Presentation", "Slide 1", "Layout 1", "Adobe Acrobat Document", "stdin", "arXiv:...", "admin", "Microsoft Office User", "Acrobat Distiller", "PDFCreator", "PC" are ignored. The PDF creation date supplies a weak year: only 1993 (PDF did not exist before) up to the current year counts, so the epoch default is rejected, and it is labeled `pdf-created`, last in the year precedence. DOI: the sidecar, then the PDF's own metadata, then the text pattern chosen by `select_doi`: a DOI in parser-labeled header/footer/aside text or removed running text of pages 1 to 2 (labeled ones first); else a text of page 1 or 2 that starts with a "doi"/doi.org label; else a labeled DOI among the first 12 body blocks of page 1; else a bare DOI only if it is the single distinct DOI on page 1. `page_footnote` text, the separated reference list, and later prose never supply a DOI, and several unlabeled DOIs give none (stored lowercase; cut at a second DOI after "," or ";", at a "?" query string, and of trailing punctuation and dashes; balanced parentheses kept). Language: `detect_language` is the only function that names the detector (`langdetect` with seed 0 over up to 5,000 characters of longer body paragraphs; none for too little text) and returns a base code ("en"); replacing the detector changes that function only. Precedence per field: sidecar, mineru, pdf for title and authors; sidecar, mineru, pdf-created for year; sidecar, pdf, text pattern for DOI; sidecar, langdetect for language.
- *Sidecar.* `<original filename>.metadata.json` next to the original. The shape is not documented anywhere; the only record is the prototype's `authors` (a string) and `year`. The reader accepts `title`, `authors`/`author` (string or list), `year` (a number or text containing a four-digit year), `doi` (bare, `doi:`, or URL), and `language`/`lang`; there are no other aliases (`date`, `published`, and `publication_year` were removed: they are not documented, and an unrelated key must not be read as a year). Unknown keys are ignored, empty values do not override, and an exact key beats its alias. A string `authors` is the user's own correction and is taken verbatim, never run through the extracted-line filters (no word-count limit, no affiliation, parenthesis, or marker stripping): it is cut only at ";", else at " and "/"&"/" und "/" и " and at commas that clearly separate full names; "Last, F., Last, F." and "Last, First" stay one author each, an ambiguous comma list ("Plato, Aristotle") stays one verbatim author, and a list value is kept entry by entry. `language` is reduced to the base code `detect_language` returns ("en_US" and "English" give "en"; an unrecognized value is kept lowercased). A value that yields nothing usable raises `MetadataError` instead of falling back to the extracted value, and so does an invalid `year`, `doi`, or type: the sidecar is the user's own text, so a mistake is shown (and fails that document only). Malformed JSON, a non-object, or an invalid field raises `MetadataError` naming the file (and line/column or field), never its content. Real sidecars were not opened by hand or printed; only the code read them during the content-free runs.
- *CLI.* `inspect` loads nothing heavy. `inspect --all` prints one record per document (not padded columns, which would be as wide as the longest title); values are single-line and control characters and bidirectional overrides are shown as "?". Redirected stdout and stderr are switched to UTF-8, and an unencodable character is replaced instead of failing; a terminal keeps its encoding (the Windows null device reports itself as a terminal with a code page, which crashed the first version). A failure to write the output (a closed pipe) is reported as such, not as a load failure. Unknown id, missing cache, broken sidecar, and an unreadable library each print one message and exit 1; giving both or neither of `<doc_id>` and `--all` exits 2.

**Limitations.**

- A title that MinerU splits into several level-1 blocks yields only the first, and a journal banner labeled level 1 would be taken as the title; the spot-check should look for both.
- Authors are heuristic and cover one name line; a comma list of single surnames "Smith, Jones" is ambiguous with "Last, First" and is read as one author (in a sidecar string it is likewise kept verbatim as one author, so a sidecar with such a list should use ";" or a JSON list). The PDF creation date is a weak year (when the file was made, not when the work was published); it is labeled `pdf-created` and every consumer can tell it from a real publication year.
- A document whose own DOI appears only in prose, or unlabeled among several DOIs on page 1, gets no DOI from the text (the sidecar or PDF metadata fill it); a labeled DOI in the first 12 body blocks of page 1 is trusted even if it is a cited one when the own DOI is absent. A DOI containing "<" or ">" (old SICI forms) is cut at that character, and a DOI broken across a line is truncated at the break; neither is marked.
- Dehyphenation across a page or block break (a paragraph continued on the next page) is not repaired. A compound outside the prefix/suffix/opposition-pair lists and the document's own vocabulary (for example "client-server", "long-term", "high-resolution") is joined: there is no dictionary. The lists are English plus Russian particles only.
- Running-text detection removes a short edge paragraph that is identical (or differs only in a page-number-like paragraph) on a quarter of the pages of a document of at least 6 pages; an identical refrain or source line at the page edge on every page is indistinguishable from a footer and is removed. A header that carries its page number inside longer text is not recognized. Footnotes, table notes, and numbered labels are kept.
- The reference list is separated by headings in the listed languages, parser labels, and the language-independent trailing-run fallback; that fallback needs at least three citation-shaped entries at the end of the document, so a list under an unlisted heading in the middle of the document, or an unheaded list with fewer than three entries or mostly non-citation-shaped entries, stays in the body. A paragraph-opened list (no heading label) needs citation-shaped paragraphs after it, so an unlabeled "References" line followed by entries that have no year or exceed 450 characters is not detected. A heading-opened list ends at the first table, figure caption, equation, or code block. Entries around parser-labeled lists are pulled in only when they are adjacent and entry-like; a plain unnumbered paragraph between entries ends the run, so interleaved notes in a note section can remain in the body (the "Check" line of `inspect <doc_id>` shows a count for numbered, citation-shaped ones), and a numbered paragraph directly next to a labeled list (a numbered step before a bibliography) is taken for an entry. An endnote section whose heading is not a reference keyword ("Notes") is separated only through its parser-labeled blocks and the entries around them. References are not parsed into fields (out of scope).
- Contents pages (`index`) and image content are dropped; images keep only captions. Markdown input recognizes captions only by a leading Figure/Table-style label, reads indented code blocks as paragraphs, flattens nested lists, and skips YAML front matter without reading title or authors from it.
- `README.md` does not yet mention `ragshelf inspect`; it was outside this task's edit boundary.
- **Dependencies.** `pymupdf` is no longer imported anywhere under `src/ragshelf/documents/` or `tests/documents/` (two tests mention the name only to assert that it is not loaded): PDF metadata is read with `pypdf`, declared in `pyproject.toml`, which matches ADR 0002's removal of `pymupdf` (it overlaps MinerU's `onnxruntime-directml`). `pyproject.toml` still lists `pymupdf` itself; removing it with the old loaders is T009's scope. **`langdetect` remains an open decision for the user** (Open Questions above): it is isolated in `detect_language`, so keeping, replacing, or dropping it touches that one function. T011 chose LLM-based detection for queries; that does not cover document language.
